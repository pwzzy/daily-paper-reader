## 摘要
优化问题的自然语言描述可能不完整，或对求解器所需的数值信息表述模糊，包括成本、容量、需求、边界和惩罚项。语言模型可以将描述转换为代码，但当所需数值缺失时，它必须停止或进行猜测。我们提出 SAILOR，一个概念验证系统，它检测此类缺乏支持的数值选择，向用户提出有针对性的后续问题，并在返回解之前更新优化模型。问题根据不确定性和求解器推导出的估计进行优先级排序，这些估计衡量每个缺失值对当前模型的影响强度。我们使用返回真值的理想化模拟器，在来自七个掩码基准的 1,723 个实例上评估该流程。在不同数据集上，精确目标值一致率从 27.0% 到 87.6% 不等，平均每个实例需 1.4--5.7 个问题。这些结果确立了在受控的分支-揭示反馈下的可行性；它们并未衡量与人类用户交互时的性能，也未衡量一般的结构性模型修复。代码见：https://github.com/sshaghayeghs/SAILOR。

## Abstract
Natural-language descriptions of optimization problems may be incomplete or vague about numerical information that a solver requires, including costs, capacities, demands, bounds, and penalties. A language model can translate the description into code, but when a required value is absent it must either stop or guess. We present SAILOR, a proof-of-concept system that detects such unsupported numerical choices, asks the user targeted follow-up questions, and updates the optimization model before returning a solution. Questions are prioritized using uncertainty and solver-derived estimates of how strongly each missing value affects the current model. We evaluate the pipeline on 1,723 instances from seven masked benchmarks using an idealized simulator that returns ground-truth values. Exact objective-value agreement ranges from 27.0% to 87.6% across datasets, with 1.4--5.7 questions per instance on average. These results establish feasibility under controlled branch-and-reveal feedback; they do not measure performance with human users or general structural model repair. Code is available at: https://github.com/sshaghayeghs/SAILOR.

## 1. 核心问题与整体含义

- **背景**：近年来出现大量将自然语言优化问题描述自动翻译为可执行数学规划（Gurobi 代码）的系统（OptiMUS、Chain-of-Experts、LLMOPT、ORLM、DeepOR 等），但这些系统几乎都在**数值信息已完整给出**的描述上评测。
- **现实痛点**：普通用户往往并不知道一个优化模型需要哪些数值（加班成本、可用产能、缺货惩罚、服务水平下界等），因此初始描述天然存在**数值欠定（numerical underspecification）**。当关键数值缺失时，LLM 翻译器要么失败、要么静默使用默认值或凭空猜测；即使猜出的值能生成可执行代码，求解结果也可能对应**另一个完全不同的问题**。
- **核心问题（Problem 1）**：给定欠定描述 $I_0$、未知隐参数向量 $\theta^*$ 和 $K$ 轮提问预算，如何选择一系列澄清问题并更新参数估计 $\tilde\theta^{(K)}$，使目标值误差 $\text{ErrObj}$ 最小化。
- **整体含义**：论文提出 SAILOR，把"一次性翻译"改为"翻译—发现缺失—追问—修复—重解"的闭环，目标是让用户**无需预先写出完整数学规格**也能得到正确求解结果。这是一个概念验证（proof-of-concept）工作，定位在受控理想化反馈下的可行性验证。

## 2. 方法论

### 2.1 核心思想
翻译器输出可执行代码的同时，**记录所有"被迫猜测"的数值**；系统对这些无依据字面量建立信念分布，用**求解器扰动**估计其重要性，再按"信息增益 × 影响程度"排序生成追问，用户回答后通过 AST 编辑改写代码并重解，循环直到收敛或预算耗尽。

### 2.2 关键流程
- **LLM 翻译**：把 $I_0$ 译为 Gurobi 代码 + 引入数值及其语义角色记录；失败可触发修复，另有一次独立验证调用。交互阶段不再重新翻译原文。
- **参数识别**：用 AST 解析生成代码，把数值字面量分为 *Known*（出现在原文，用正则从文本抽取，可处理 `40` 与 `40.0` 等等价形式）与 *Guessed*（原文缺失、由 LLM 补充）；通过值与名称相似度关联。**注意：不处理 "forty" 这类数词，歧义匹配可能悬空。**
- **高斯信念模型**：每个未解析参数 $\theta_i \sim \mathcal N(\mu_i,\sigma_i^2)$，$\theta_i\in[\ell_i,h_i]$，初值 $\mu_i$ 取 LLM 猜测，默认区间 $[0.01\mu_i,100\mu_i]$；定义三种更新：精确更新（点质量，$\sigma_i\to0$）、概念上的二值更新、软更新（向 LLM 精化值按固定权重混合）。不确定性用微分熵 $H_i=\frac12\log(2\pi e\sigma_i^2)$ 度量，已解析参数熵取地板值 $-50$。
- **重要性打分**：对每个参数在信念范围内扰动并重解，组合四项归一化诊断量：
  $$s_i = w_{sw}\phi_{sw} + w_{gr}\phi_{gr} + w_{sh}\phi_{sh} + w_{bd}\phi_{bd}$$
  分别对应目标值摆幅、局部有限差分灵敏度、相关影子价格最大幅值、相关约束紧约束比例；权重固定为 $(0.40,0.30,0.15,0.15)$。每次交互后重算（解析一个参数会改变其余参数的灵敏度结构）。混合整数/非线性模型中若求解器不提供对偶/松弛信息，相应分量为 0。
- **问题生成与评分**：候选问题分三类——直接问值、二值区间切分（高于/低于阈值）、确认当前估计。评分函数为
  $$\text{score}(q)=\Delta H(q)\, g(s_i),\quad g(s_i)=\alpha+(1-\alpha)s_i,\ \alpha=0.5$$
  即"期望熵减 × 单调递增的重要性缩放"，下一问取 $\arg\max_q \text{score}(q)$。重要性**只用于排序**，不单独解析或丢弃参数。
- **答案处理与代码改写**：五步——更新信念 → AST 改写对应字面量 → 重解 Gurobi → 重算未解析参数重要性 → 可选让 LLM 精化剩余猜测（经软更新进入）。
- **停止条件**（任一触发）：(i) 全部后验 $\sigma_i<10^{-8}$；(ii) 总熵低于 $H_{\min}=-40$；(iii) 熵改进不足 0.1 且连续 $N_{stall}=5$ 轮无参数被填充；(iv) 预算 $K=30$ 用完。

### 2.3 Benchmark 构造方法（贡献之一）
从**完全指定**的实例出发：LLM 译为 Gurobi 代码 → AST + 模型检查抽取全部数值常量（列表/字典展平为标量）→ 按 ×{0.5, 0.8, 1.2, 2.0} 扰动重解，融合目标灵敏度、解灵敏度、可行性影响得到结构重要性排名 → 对排名靠前的参数用"某个速率""一定工资"等模糊措辞掩码，并可自然化改写。**保留真值向量 $\theta^*$ 用于自动评分**。

## 6. 主要结论与发现

- **交互式恢复在所有 7 个数据集上都优于"保留初始猜测"基线**：精确一致率从 NL4LP 的 87.6% 到 ComplexLP 的 27.0%，平均提问 1.4–5.7 次；No-interaction 基线对应仅 5.6%–34.2%（下降 21.3–71.3 个百分点）。
- **容差放宽后提升明显**，尤其 ComplexLP：≤10% 一致率从 27.0% 提升到 62.6%。
- **翻译保真度是决定性瓶颈**：把翻译模型换成 GPT-4o-mini，NL4LP 精确率从 87.6% 跌到 44.4%，IndustryOR 从 64.3% 跌到 9.5%，ComplexOR 从 50.0% 跌到 22.2%——影响远大于任何问题排序策略的效应。**求解器辅助交互无法修复一开始就翻译错的优化结构。**
- **求解器派生的优先级排序未显示宏观收益**：去掉后宏平均从 66.4% 变为 66.1%（各数据集正负不一），因此开源默认退回**均匀重要性**。
- **可选精化效果混杂**：去掉后宏平均从 66.4% 降到 64.2%，但 7 个数据集中 4 降 1 平 2 升，属探索性结果。
- **先验范围与问题预算**的敏感性在各数据集间方向不一致，机制未被隔离。
- 总体定位：在受控分支-揭示反馈下**证明可行性**，但**不构成对人类用户表现、纯二值反馈或结构性模型修复的证据**。

## 7. 优点

- **问题定义有新意且务实**：把"数值欠定"从翻译任务中显式切分出来，指出现有 NL-to-solver 基准"按构造排除了该设定"，填补了评测空白。
- **基准构造流程可复用**：AST 级常量抽取 + 求解器扰动排序 + 定向掩码 + 保留真值，形成一套可自动评分的欠定实例生成方法（贡献二）。
- **端到端闭环设计完整**：信念建模 → 重要性打分 → 问题评分与选择 → AST 改写 → 重解 → 停止判据，各环节均有明确公式与实现细节。
- **问题排序准则有理论支撑**：将主动学习/偏好 elicitation 的熵减准则与决策聚焦学习（decision-focused learning）思想结合，用 $g(s_i)$ 单调缩放保证"不确定性不会因重要性权重而被淹没"。
- **学术诚实度突出**：作者主动标注基准构造的循环性、信念模型的类型不匹配（负值/零值/整数/有界参数）、指标只衡量目标值一致而非字面量或最优解恢复、ComplexLP 完整输入优于交互输入等多项威胁。
- **可复现性**：提供开源代码，并特别注明"复现主配置需重新启用求解器派生分数"，避免默认配置带来的复现歧义。

## 8. 不足与局限

- **交互过于理想化**：模拟器确定性作答、完美记忆，且二值/确认问题都会直接揭示精确值，因此测得的是**分支-揭示**下的上限；真实用户的近似、拒答、单位不一致等均未覆盖，提问数不能直接外推到人机交互。
- **基准构造循环性**：掩码信号与恢复期重要性打分同源，系统性偏袒本方法；需要按结构角色独立掩码或随机选择可抽取字面量来对照。
- **消融未解耦**：No-interaction 基线同时缺少交互与精化，无法分离二者贡献；缺少配对记录与因子设计。
- **指标范围有限**：只比较目标值与基准答案，不验证逐字面量恢复、可行域等价或特定最优解恢复；"已解析字面量比例"也不是被掩码真值参数的恢复率。
- **信念模型不匹配**：原始尺度高斯 + 乘性区间不适合负值、零值、有界、整数字面量；截断后熵公式仅为近似，先验范围实验只是有限的敏感性检查。
- **小样本数据集**：IndustryOR（42）与 ComplexOR（18）的结论统计效力弱。
- **强翻译器依赖**：方法绑定昂贵强模型，翻译器能力与交互机制的价值相互纠缠，实验无法分离；且**无法修复结构性翻译错误**。
- **结构性修复缺口**：论文明确将"结构模型修复与求解器辅助参数恢复的结合"

 这一方向明确列为未来工作。当初始描述遗漏的是约束、变量或目标结构而非数值时，数值层面的追问与 AST 字面量改写完全无能为力，方法的能力边界被牢牢限定在"结构已正确、仅数值缺失"的情形。

- **反馈假设的系统性偏差**：二值区间问题在真实场景中本应只提供"高于/低于阈值"的一位信息，确认问题本应只返回是/否判定，但模拟器在作答后**一律揭示精确值**。这使每个问题实际携带的信息量远大于其名义类型，期望熵减 $\Delta H(q)$ 的估计与真实信息增益不再匹配，从而削弱了问题排序策略（尤其是重要性缩放项 $g(s_i)$）之间的可区分度——"求解器辅助排序无宏观收益"这一结论，可能部分源于该偏差压缩了排序策略的发挥空间。
- **真值查找的脆弱性**：三级回退机制中，模糊匹配与 LLM 抽取都可能返回与原模型语义一致但数值口径不同的"伪真值"（单位、量纲、时间粒度差异）；连续 3 次失败即锁定当前估计的设计，虽保证了鲁棒性，却会**静默掩盖匹配失败**，使这些实例被计入最终指标而不被单独报告。
- **适用场景未验证**：实验集中于 LP、MILP 与少量非线性实例，多目标规划、随机/鲁棒优化、非凸问题、以及参数间存在耦合约束（如预算分摊、比例关系）的情形均未涉及；在这类模型中，单参数扰动打分与独立高斯信念的前提都难以成立。
- **成本与交互延迟未评估**：每轮交互都需重解 Gurobi（最多 30 秒上限）并可触发额外 LLM 调用，但论文未报告端到端墙钟时间、API 调用次数或 token 消耗，因而无法判断该闭环在真实交互场景下的响应可接受度。
- **缺少人类用户研究**：全部结论建立在确定性模拟器之上，没有真实被试实验，因此"提问数""问题类型偏好""用户是否愿意回答"等可用性维度均无实证支撑。

## 9. 总体评价与启示

- **贡献定位**：这是一篇"问题定义 + 基准构造 + 可行性验证"三位一体的工作，其最大价值不在算法性能本身（求解器辅助排序被证明无宏观收益、可选精化效果混杂），而在于**把一个此前被基准设计系统性回避的设定——数值欠定——正式提上台面**，并给出可自动评分的构造范式。
- **最强结论**：翻译保真度是压倒性的主导因素。同一套交互机制下，更换翻译模型可使精确一致率在 NL4LP 上从 87.6% 掉到 44.4%、在 IndustryOR 上从 64.3% 掉到 9.5%，其影响幅度远超任何问题排序、先验范围或预算策略的效应。这提示后续工作应优先投入**结构化翻译与模型自检**，而非更精细的提问策略。
- **方法论启示**：将"不确定性度量（微分熵）"与"决策相关性度量（求解器扰动诊断）"相乘作为问题评分，是把主动学习与决策聚焦学习结合的一个自然范式；但本文的负结果说明，在**反馈信息被过度理想化、且重要性信号与基准构造同源**的条件下，这一结合难以展现优势——其真正潜力有待在更诚实的反馈协议下重新检验。
- **对后续研究的建议**：(i) 引入真实用户或至少采用**纯二值/纯确认**的受限反馈协议，重新评估问题排序；(ii) 用与恢复期打分**相互独立**的信号（如结构角色、随机抽样字面量）构造掩码，破除循环性；(iii) 采用配对因子设计分离"交互"与"精化"的贡献；(iv) 把信念模型扩展到对数正态、离散/整数、带符号与有界等与参数真实类型匹配的分布；(v) 将结构修复纳入同一闭环，使系统能同时追问"缺哪些约束"与"缺哪些数值"。
- **一句话总结**：SAILOR 证明了在受控理想反馈下，LLM 翻译器"承认自己猜了什么"并据此追问，确实能显著缩小欠定描述带来的目标值误差；但它同时诚实地划出了边界——**交互只能修复数值，不能修复结构；而结构翻译的质量，才是决定成败的那一环**。
