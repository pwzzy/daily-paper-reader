## 摘要
二次无约束二值优化（QUBO）是组合优化的核心建模形式，因其与量子、混合量子-经典以及量子启发式求解器的兼容性而受到越来越多的关注。然而，将自然语言问题描述转化为正确的 QUBO 公式仍然困难，需要识别二值变量、约束、目标函数、惩罚项以及合适的惩罚权重。这一过程耗时，且通常需要大量领域专业知识。为应对这一挑战，我们提出了一种端到端多智能体框架，能够从自然语言问题描述自动生成 QUBO 公式，并得到结构化或非结构化测试用例的支持。为评估其性能，我们还引入了 QUBOBench，一个包含 12 个应用领域中 100 个组合优化问题的基准，这些问题整理自同行评审文献、竞赛以及经典 NP 难问题。实验结果表明，我们的框架在 QUBOBench 上达到 68% 的准确率，比直接单次调用的基线高出 22%。进一步分析表明，迭代式自我修复是促成性能提升的最重要组件。数据和代码已在 https://quitttcat.github.io/QuantumQUBOAgent 开源。

## Abstract
Quadratic Unconstrained Binary Optimization (QUBO) is a central formulation for combinatorial optimization and has gained increasing attention due to its compatibility with quantum, hybrid quantum-classical, and quantum-inspired solvers. However, translating natural-language problem descriptions into correct QUBO formulations remains difficult, requiring the identification of binary variables, constraints, objective functions, penalty terms, and suitable penalty weights. This process is time-consuming and often demands substantial domain expertise. To address this challenge, we propose an end-to-end multi-agent framework that automatically generates QUBO formulations from natural-language problem descriptions, supported by structured or unstructured test cases. To evaluate its performance, We also introduce QUBOBench, a benchmark containing 100 combinatorial optimization problems across 12 application domains, curated from peer-reviewed literature, competitions, and canonical NP-hard problems. Experimental results show that our framework achieves 68% accuracy on QUBOBench, outperforming a direct single-call baseline by 22%. Further analysis identifies iterative self-repair as the most important component contributing to improved performance. The data and code are open-sourced at https://quitttcat.github.io/QuantumQUBOAgent.

## 2. 方法论

### 2.1 核心思想
- 不依赖单次 LLM 调用一次性完成全部步骤，而是将任务分解为多个专门化智能体，每个智能体负责一个步骤，并通过 **Judge 检查点 + 迭代自修复反馈回路** 形成闭环。
- 目标输出：经正确性验证的 QUBO 公式 $F$、可构造任意实例 QUBO 矩阵的 builder 函数 $f$、示例、LaTeX 撰写与编译后的 PDF。

### 2.2 多智能体架构（6 个 LLM 智能体 + 1 个确定性组件）
- **Planner Agent**：读取自然语言问题，抽取决策变量、优化方向、所有隐式/显式约束及其类型与软硬性质，输出结构化 JSON；若 Judge 发现不一致，则依据问题列表重新解析规划。
- **Formulizer Agent**：基于 Planner 的 JSON 推导 QUBO 代价函数，简化后返回含变量映射、目标项与罚项、罚权重理由、常数偏移量的结构化 JSON；接收 Judge 反馈及流水线末端失败测试用例的反馈。
- **Judge Agent**：在两个检查点被调用——(1) 校验 Planner 规范与原始描述的一致性；(2) 校验 Formulizer 的 QUBO 代价与规范的一致性（约束编码、罚项形式、目标符号）。返回通过/不通过与具体问题列表，反馈回原智能体重试。
- **Debugger Agent**：本质是解析器，将用户提供的测试用例与真值从自然语言转为结构化 JSON；利用变量映射把最优选择编码为比特串。**不接触 Coder 输出与生成的 QUBO 矩阵**，避免把生成公式的解当作真值。
- **Coder Agent**：将 QUBO 公式翻译为可执行 Python 代码。仅获得结构化规范、公式与单个样本实例参数，**不接触真值比特串**，防止信息泄漏。
- **Test Runner（非 LLM，确定性组件）**：对每个测试用例验证 Coder 输出与真值，将失败分类为：
  - **编码错误**（异常或函数格式错误）→ 回传 Coder Agent；
  - **公式化错误**（输出合法但最优解与真值不符）→ 回传 Formulizer Agent 重新推导。
- **Writer Agent**：生成输出的可视化表示与摘要。

### 2.3 算法流程（文字说明）
1. 输入自然语言问题描述 $P$、测试用例集合 $T$、各阶段重试预算 $R_{planner}, R_{formulizer}, R_{coder}$ 与通过阈值 $\tau$。
2. Planner 生成规范 spec → Judge 校验；若未通过，Planner 依据 issues 重试至多 $R_{planner}$ 次；仍不通过则 Fail。
3. Formulizer 依据 spec 生成公式 → Judge 校验；若未通过，依据 issues 重试至多 $R_{formulizer}$ 次；仍不通过则 Fail。
4. Debugger 依据 spec、公式变量映射与样本输入生成结构化测试用例。
5. 循环至多 $R_{coder}$ 次：Coder 生成代码 → Test Runner 运行并分类结果 → 计算通过率；若通过率 ≥ τ，则 Writer 生成 LaTeX 并返回公式、代码、LaTeX；若为公式化错误，则 Formulizer 重新推导并再次经 Judge 校验；否则更新错误信息进入下一轮。
6. 循环结束仍未达标则 Fail。

### 2.4 关键设计细节
- QUBO 形式：$\min_{x\in\{0,1\}^n} E(x) = x^\top Q x + c$，其中 $Q$ 为系数矩阵，$c$ 为常数偏移。
- 信息隔离机制：Coder 不见真值、Debugger 不见生成矩阵，保证评测客观性。
- 重试预算与通过阈值 $\tau$ 是控制质量与成本的核心超参。

## 6. 主要结论与发现

- **准确率**：完整 QuantumQUBO Agent 在 QUBOBench 上达 **68%**，直接单次调用基线为 **46%**，提升 **22 个百分点**。
- **消融结果**：
  - 移除迭代反馈后准确率骤降至 **35%**，是最大跌幅，说明**迭代自修复是最关键组件**。
  - 移除 Judge 与迭代反馈后为 **36%**，与无重试设置几乎相同，说明 **Judge 只有在配合足够重试预算时才产生价值**。
- **错误分布**：
  - 框架的错误中 **79.3% 来自 Coder**（索引 bug、数组形状错误、NumPy 操作不当等），仅 **15.5%** 来自公式化失败——说明 Planner-Formulizer-Judge 链路能解决大部分数学歧义。
  - 直接方法相反：**66.0%** 为公式化错误，仅 26.4% 为编码错误——说明单次 LLM 调用主要困难在于推导正确的 QUBO 数学，而非实现。
- **Token 消耗**：完整流水线 48.1K tokens，显著高于直接方法 3.2K，即准确率提升伴随成本增加。
- **未来工作方向**：为特定任务微调各智能体；引入 Ising 公式化器并结合量子硬件反馈。

## 7. 优点

- **任务分解合理**：将复杂建模流程拆分为规划、公式化、编码、调试、评判、撰写等专门角色，符合该任务的认知结构，降低单次调用的认知负荷。
- **闭环自修复机制**：Judge 检查点 + Test Runner 错误分类 + 定向反馈重试，构成可解释、可定位的迭代改进流程，是性能提升的核心。

- **评测公平性考量**：直接基线提供结构化实例字典并约束固定函数签名，消除格式导致的假阴性。
- **开源**：数据与代码开放，利于可复现研究与后续比较。
