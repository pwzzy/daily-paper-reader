## 摘要
工具使用基准测试通常评估智能体是否使用合适的工具和有效的参数来完成工作流。然而，在路线规划和车队调度等实际决策场景中，仅可行性是不够的。个体选择通过共享约束和成本相互影响，因此可行的解决方案可能仍然明显次优。这引出了一个更困难的问题：智能体能否将通过工具收集的信息转化为全局最优决策？我们提出了AlgoWorlds，这是一个将形式化指定的组合优化问题转化为具有可验证全局最优的部分可观测决策环境的基准测试。每个环境包含一个隐藏实例，该实例只能通过特定任务的信息工具进行观察，随后智能体做出一个结构化决策，并对该决策的可行性和最优性进行评估。AlgoWorlds包含240个环境，涵盖十个组合优化族和四个工作负载级别。族特定的确定性程序生成实例，精确算法验证其最优解并确定工作负载级别，两种结构不同的工具接口呈现每个底层实例。我们评估了七个领先的大语言模型（LLM），包括Claude Opus 4.8和GPT-5.6 Sol。实现全局最优仍然极具挑战性：尽管领先模型在大多数情况下能做出可行决策，但表现最好的模型仅在38.61%的案例中达到精确最优。即使智能体收集了足够的信息来重构隐藏实例，大多数失败最终仍导致可行但次优的决策。因此，这一挑战不仅限于信息获取，还涉及信息整合、全局约束推理和决策验证。项目主页可在https://xzx34.github.io/AlgoWorlds/上访问，代码可在https://github.com/xzx34/AlgoWorlds上获取。

## Abstract
Tool-use benchmarks generally evaluate whether an agent completes a workflow using appropriate tools and valid arguments. However, feasibility alone is insufficient in real-world decision settings such as route planning and fleet dispatch. Individual choices interact through shared constraints and costs, so a feasible solution may still be substantially suboptimal. This raises a harder question: can an agent turn information gathered through tools into a globally optimal decision? We introduce AlgoWorlds, a benchmark that transforms formally specified combinatorial optimization problems into partially observed decision environments with verifiable global optima. Each environment contains a hidden instance observed only through task-specific information tools, after which the agent commits to one structured decision evaluated for feasibility and optimality. AlgoWorlds contains 240 environments covering ten combinatorial optimization families and four workload levels. Family-specific deterministic programs generate the instances, exact algorithms certify their optima and determine workload levels, and two structurally different tool interfaces present each underlying instance. We evaluate seven leading LLMs, including Claude Opus 4.8 and GPT-5.6 Sol. Achieving global optimality remains highly challenging: although leading models produce feasible decisions in most cases, the best-performing model reaches exact optimality in only 38.61% of cases. Even when agents collect sufficient information to reconstruct the hidden instance, most failures end in feasible but suboptimal decisions. The challenge therefore extends beyond information acquisition to information integration, global constraint reasoning, and decision verification. The project homepage is available at https://xzx34.github.io/AlgoWorlds/, and the code is available at https://github.com/xzx34/AlgoWorlds.

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想：算法世界（Algorithmic World）

一个算法世界被形式化为一个五元组：

\[w = \{q, \mathcal{I}, \mathcal{T}, f_c, b\}\]

- \(q\)：文本问题，说明决策目标、约束条件与优化目标。
- \(\mathcal{I}\)：隐藏的优化实例，是决定可行决策和客观值的全部私有数据（智能体不可直接访问）。
- \(\mathcal{T}\)：任务专用工具集，包含多个信息工具 \(\mathcal{T}_{info}\) 和一个最终决策工具 \(t_{dec}\)。
- \(f_c\)：成本函数，定义每个信息工具的调用开销。
- \(b\)：预算上限——智能体在整条轨迹中调用工具的总成本不得超过该值。

### 2.2 交互流程

智能体只能看到 \(w \setminus \mathcal{I}\)，通过反复调用信息工具获取实例片段，最终调用 \(t_{dec}\) 提交一个结构化决策：

\[\pi(w \setminus \mathcal{I}) \rightarrow t_{s_1} \rightarrow o_{s_1} \rightarrow \cdots \rightarrow t_{s_k} \rightarrow o_{s_k} \rightarrow t_{dec}(y), \quad \sum_{i=1}^{k} f_c(t_{s_i}) \le b\]

\(t_{dec}\) 零成本且只能调用一次；信息工具可重复调用，若剩余预算不足则调用被拒绝但不产生任何成本。

### 2.3 三类关键度量定义

文中定义了多条评估指标，下文公式给出了其中的核心部分：

- **Exact optimality**（精确最优率，主指标）：

\[E_w(y) = \begin{cases} 1, & F_w(y)=1 \;且\; \Delta_w(y)=0 \\ 0, & \text{otherwise} \end{cases}\]

其中 \(\Delta_w(y) = |v_w(y) - v^\star_w|\) 是最优性间隙，\(v^\star_w\) 表示已认证的最优目标值。

- **Reference utility**（参考效用）：

\[U_w(y) = \begin{cases} \max\{0,\; 1 - \Delta_w(y)/\Delta_w^{ref}\}, & F_w(y)=1 \\ 0, & F_w(y)=0 \end{cases}\]

其值在最优点处为 1、在预设的参考次优点处为 0。

- **Information sufficiency** 与 **Discovery coverage**（轨迹诊断指标）：

\[C_w(\tau) = 1[D_w(\tau)=1], \qquad D_w(\tau) = \max_{S \in \mathcal{S}(w)} \frac{|\mathcal{A}_w(\tau) \cap S|}{|S|}\]

用于判断轨迹中收集的信息是否足以重构隐藏实例并获得最优解。

### 2.4 构建流程：三个关键设计

1. **确定性实例生成**：每个任务族使用人工编写、无随机性的确定性生成器，依据“规模配置 + 结构配置”生成可复现的隐藏实例，从而控制系统性地变化问题规模和决策耦合结构。
2. **精确最优解与工作量标定**：用族专属的精确算法求出每个实例的全局最优解，并以算法实际执行的五类基本操作数（访问状态数、检查转移数、约束检查数、值更新数、重构组件数）来定义四个工作量层级：

\[Work(\mathcal{I}) = N_{state} + N_{transition} + N_{check} + N_{update} + N_{reconstruct}\]

各层级带宽为 \([2^{15},2^{17}]\)、\([2^{19},2^{21}]\)、\([2^{22},2^{24}]\)、\([2^{24},2^{26}]\)。
3. **双工具接口（Direct/Mediated）构境**：同一隐藏实例通过两种结构不同的信息工具关系呈现为两个算法世界——共享相同的 \(q, \mathcal{I}, f_c, b\)，但信息记录的组织和关联方式不同，用于度量智能体对信息呈现形式的敏感性。

### 2.5 质量控制（数据质量验证）

- 每个实例用两条不同方向/表示的独立精确算法求解，二者须在最优决策、目标值及唯一性上完全一致。
- 用决策检查器复算可行性及目标值。
- 验证两种信息采集路径在预算之内足以重构隐藏实例并恢复最优解；同时确认穷举调用所有工具的代价必然超过预算。
- 对各信息通道和响应进行反事实检查与接口等价性检查，确保信息确实分散在不同来源中，且两种接口编码的是同一决策问题。

## 6. 主要结论与发现

1. **全局最优对当前 LLM 仍极富挑战**：最佳模型 Claude Opus 4.8 精确最优率仅 38.61%，GPT-5.6 Sol 为 38.19%，没有模型超过 40%。
2. **可行性目标几乎被满足、最优性目标远未达到**：Claude Opus 4.8 和 GPT-5.6 Sol 的可行性分别为 96.25% 和 97.50%，但在超过一半情形下提交了可行但非最优的决策。
3. **信息获取≠最优决策**：GPT-5.6 Sol 最优模型有 89.86% 的轨迹收集到足以重构隐藏实例的信息，但其中只有 41.58% 达到全局最优，56.26% 止步于可行但次优，说明失败主要源于信息整合和全局推理而非信息缺乏。
4. **任务族间差异巨大且不遵循经典复杂度规律**：Basket Assembly 表现最好（多个模型达 100% 精确最优），而 Transit Routing、Series Portfolio、Machine Layout、Sequential Matching、Evidence-Joined Routing 上所有模型基本都 <10%。尽管 Transit Routing 精确算法最坏情况为多项式复杂度、Basket Assembly 为指数复杂度，LLM 却在指数问题上表现更好，说明跨族差异不能用算法渐近复杂度简单解释。
5. **工作量层级与性能有整体负相关**：所有模型在 L4 的精确最优率和参考效用均低于 L1，参考效用随层级单调递减的模型有 6/7，说明基于算法工作量标定的难度维度对 LLM 有区分度。
6. **接口敏感性整体较小，但存在部分模型差异**：7 个模型在 Direct 接口上的成绩均略高于 Mediated（ΔD−M = +0.6%~+6.4%），315~343/360 个配对结果相同；仅 GPT-5.6 Sol 与 Claude Sonnet 5 的配对 bootstrap 95% 置信区间不包含零。
7. **失败模式的综合画像**：当前 LLM 在做这种工具决策时，较擅长采集信息、产出可行方案，但缺乏将分散信息做全局耦合推理并验证最优性的能力。

## 7. 优点

1. **基准定位填补空白**：此前工具使用基准以“任务完成”为准，AlgoWorlds 首次系统性把“全局最优决策”作为核心轨道，将问题推向更接近真实业务决策的难度层面。
2. **可靠且可审计的最优解**：每个实例都有两份不同实现路径的精确算法共识作为全局最优，并检查了最优决策的唯一性，评分可精确判定，不需要近似模型或 LLM 自行判断。
3. **信息完整性与决策质量解耦**：同时设计“最终决策指标”和“轨迹诊断指标”，能回答“是因信息不够失败，还是信息足够而推理不足失败”这一关键问题。
4. **工具接口配对的精巧设计**：同一决策问题、同一组事实，用两种结构上不同的信息呈现方式（Direct/Mediated），使研究能隔离“信息表达/组织”对最优决策能力的影响，实验设计较为严谨。
5. **算法逼真的工作量分层**：以精确算法真实执行的五次操作来标定难度，摆脱了传统“规模参数相同才可比”的限制，亦与模型轨迹无关，保证了公平。
6. **质量控制细致全面**：包含独立验证算法、决策检查器、信息通道反事实、响应隔离检查、接口等价性检查和发布完整性检查（内容摘要、清单绑定）。
7. **附带丰富的轨迹与条件分析**：如实体接地度、调用数、预算消耗、引用归一遗憾值、终止模式等辅助诊断，便于后续研究者深入分析失败机制。

## 8. 不足与局限

1. **模型覆盖有限**：仅 7 个闭源前沿 LLM，未覆盖开源模型社区（如 Llama、Mistral 等）或更早版本的模型；可能隐含着商业模型自身的偏好偏差，不能外推至所有模型。文中也坦承未试验增加通用代码执行/外部优化器是否显著提升能力。
2. **合成环境与现实距离**：环境为形式化生成、使用唯一全局最优解；没有考虑真实世界信息的噪声、歧义、时变属性，以及多解并列最优的普遍性。因而基准偏“结构化推理验证”而非“真实性工作负载”。
3. **充分信息集可能存在盲区**：轨迹诊断基于预定义的充分信息集判定，但“确定最优解”的方法可能不止这些集合；未完全覆盖任一充分信息集的轨迹仍有可能是最优轨迹，因此信息充分性指标可能低估部分智能体实际能力。
4. **因果推断有限**：主实验是相关性分析，而非严格的因果实验，任务族差异、规模差异的解释多为事后推理（例如复杂度不足以解释族差），没有进一步构建机制性对照去验证原因。
5. **统计报告不均衡**：主表给出了均值和标准差，但很多补充表只给均值无方差/显著性；接口差异仅对部分模型显著，没有多假设比较校正等更细致的讨论；3 次重复对某些高变异性模型（Claude Opus 4.8, Claude Sonnet 5 标准差 3.85~4.65%）可能仍然偏少。
6. **缺少端到端算力透明度**：没有给出运行全部评估的推理消耗量，其他研究者难以预估复现成本或评估模型的 API 敏感度；温度等超参数在不同供应商之间不完全可比。
